# dsh-Kingdom 2.0.0

2.0 将目标草稿、任务执行、主管审查、交付、用量与人类管理窗口放在同一个个人工作台中。默认一个执行者；独立子项适合并行时，先审核一份固定版本的协作计划，再由主管按预算、依赖与工作区约束推进。

## 功能与使用边界

- 今日工作台、任务、待我处理、王国地图、用量、设置六个入口；四主题、窄屏、键盘与减少动态效果偏好。
- 独立短时人类管理窗口，准确预览变更、确认提交、查询回执；到期、撤销、窗口替换和丢响应不会自动扩大权限或重发操作。
- 协作最多两个子项和一个独立整合者；只读资源可共享，写资源独占，接受的前置结果才可交接。子项完成后父任务仍须实际整合与单独审查。
- 用量区分实报、估计预留、未确认、共享与恢复中。软预算限制新增工作，在途请求仍可能计费；金额未知不会显示为零。
- 超时不等于执行失败，未知执行先对账；证据不足时保留占用和 RECOVERING，不自动重发。

本版不包含记忆系统、跨任务召回、自动会话续接或无限扩队。工具按需展示保持关闭，协作须明确采纳。真实人工减负和付费 Token 节省尚未完成成对测量，不宣传具体收益比例。

## 安装与兼容

参阅随包提供的 [使用指南](V2.0-USER-GUIDE.md)。验证组合是 Windows、Node 24.11.1、DSH CLI 0.1.5-rc.1 和主要组件 0.1.5-rc.2；2.0 的 DSH peer 范围明确限定在相应 rc 系列。旧宿主请使用对应旧版 Kingdom。避免在插件目录安装另一份 DSH Core。

升级前先停止新增任务并核对未决执行，做 SQLite 一致备份，在新路径恢复副本验证。WAL 模式不能只复制主数据库。正式数据库、任意旧库、v3→v4 迁移及持续并发写入备份均未在本轮执行；不能从打包成功推断迁移安全。

## 发布前修复与验证

- 已采纳计划固定执行者，拒绝会让计划永久失效的 HANDOFF；普通任务原有转交保持可用。
- 失败或中止的准确尝试经主管 REWORK 后可以重试，包括真实派发事务和多个失败子项的逐项恢复。历史未结算执行仍阻断新增工作。
- Legacy 与受治理入口双向遵守真实目录写互斥，覆盖父子目录及链接别名；检查与执行事实创建同事务，失败整体回滚。
- 管理窗口明确拒绝提交后保留输入并允许重新预览；结果未知时保留非敏感操作引用，刷新后先查询原回执，不重复发送。窄屏可完整读取计划指纹。
- 修复 Unix socket 路径过长导致的本地通信启动失败；超出系统字节上限时在创建资源前给出明确原因。完整认证与清理边界不变。
- 打包前重新编译；发布脚本在编译或测试非零退出时停止。CI 和 smoke 使用隔离 fixture，不读取用户的正式数据库。

Windows 干净工作区全量检查中 **473 项通过**；Unix 专用路径检查在 Linux CI 中验证。发布还核对隔离 smoke、准确包的官方 DSH 本地 SSE 接线、四主题与宽/窄屏 GUI、包内容与远端摘要。上述运行使用隔离数据和脚本模型，用于核对产品接线与失败路径，不代表真实付费模型质量或收益。
