## 1. DSH peer 兼容范围放宽

- 旧：`@deepseek-ai/dsh-commands` / `dsh-llm` / `dsh-tools` = `>=0.1.5-rc.1 <0.1.5`，
  `dsh-token-meter` = `>=0.1.5-rc.2 <0.1.5`。
- 新：两条版本线并列 `>=0.1.5-rc.1 <0.1.6-0 || >=0.1.7-0 <0.1.8-0`
  （`dsh-token-meter` 下界为 `0.1.5-rc.2`）。`package-lock.json` 的 peer 快照同步。
- **为什么必须分线写**：在 semver 的 prerelease 规则下，`>=0.1.5-rc.1 <0.2.0` 并**不包含**
  `0.1.7-rc.2`（只包含 0.1.5-rc 线与 0.1.8 稳定版）。分线写法是唯一能同时表达"已验证的
  0.1.5-rc 线"与"目标 0.1.7 线"且不误收未测版本的形式。
- **为什么必须改**：DSH `0.1.7-rc.2` 的 `@deepseek-ai/dsh-app-boot` 新增插件兼容性预检
  （`evaluatePluginCompatibility`，`lib/index.js:286-313`）。它只检查 `@deepseek-ai/dsh` 与
  `@deepseek-ai/dsh-*`，判据是 `semver.satisfies(runtime, range, { includePrerelease: true })`；
  `loadProfileDirectory`（`:919-955`）对 `dsh.profile.bundles` 中每个 bundle 判定，不通过且未豁免
  即抛出 → 收进 `skippedBundles` → **该 bundle 整层不加载**。症状是启动不报错，只在 stderr 留
  一行 skip 警告，而工具、`/kingdom` 命令与 GUI 会一起消失。
- **只改声明不够**：预检读取的是**已安装副本**的 `package.json`。必须重新打包并重装该 profile，
  否则升级后仍然是旧的 `<0.1.5` 声明。
- 未改 `@deepseek-ai/cordis`（`>=4.0.0-rc <5`）与 `@deepseek-ai/schemastery`（`^3.18.0`）：它们
  不在预检集合内，且 0.1.7-rc.2 携带的 4.0.4 / 3.18.4 均落在范围内。

## 2. 无 live Agent 的会话现在可以绑定席位

- **症状**：对一个刚创建、尚未产生任何消息的会话执行
  `/kingdom role.bind {"role_type":"SUPERVISOR",…,"session_id":"…"}` 会得到
  `INPUT_DENIED [SESSION_ABSENT]`，于是无法预先设置主管席位。
- **原因**：目标会话校验只接受 live Agent（`agents.get(session_id)` 返回同一条 Agent，且状态为
  `idle` 或 `running`）。DSH 的 Agent 一旦被回收就会移出注册表（`AgentStatus` 本身只有
  `idle | running`，disposal 不是第三种状态），此后该 session_id 再也过不了校验。
- **现行为**（`resolveDirectTargetSession`）：
  1. live Agent 命中 → 放行，事件记 `session_evidence: "LIVE_AGENT"`；
  2. 仅当分类为 `ABSENT`（注册表里没有这条 live Agent）时，回退到"该 session_id 已在本机 DSH
     持久会话存储中登记"的存在性证明（`ctx.sessionQuery.observeSession`，只用 header 做身份比对，
     观察租约用完即释放）→ 放行，事件记 `session_evidence: "DURABLE_SESSION"`；
  3. 两条路都证明不了 → 仍然拒绝，**零写入**。
- **没有放宽的部分**：`FOREIGN` / `MULTIPLE` / `EXPIRED` / `UNKNOWN` 一律保持 fail-closed，不因
  "可能是它"而放行；调用者身份校验（`resolveTrustedToolSession`）未改动，仍要求 live Agent；
  宿主未挂载 `sessionQuery` 时退化为原行为（拒绝并说明缺少观察通道）。Owner 管理窗口的目标会话
  校验与列表使用同一解析器，行为一致。
- **语义边界**：`DURABLE_SESSION` 只说明"这条会话属于本机 DSH"，**不说明它当前可执行**。席位在
  该会话真正启动前不能派发或复核；这条证据强度差异会记进 `ROLE_BOUND` /
  `BINDING_PROFILE_UPDATED` 事件的 `session_evidence` 字段，供审计区分。
