# Kingdom 操作台视觉升级

## 目标与依据

服务于管理多个 Agent 的使用者，让人快速识别角色、所属领地、任务状态和可执行动作。实际产品入口为 `src/gui/server.ts` 的 `/console`，三页由 `src/gui/console-app.ts` 呈现；不修改 DSH 宿主、数据库、权限或治理状态机。

2026-09-08 在本地 HTTP 合成数据预览中，使用 Computer Use 检查了当前源码：

| 实际发现 | 对应设计 |
| --- | --- |
| 1440×900 账本可见说明多为 10.88–12.48px；管理页面注释、原因难读 | 正文 14–15px，辅助信息至少 12px，任务名称 14px，清楚区分标题/内容/技术注脚 |
| 地图纹理、巨型星形、各层发光边框同时强调；领地颜色与状态色争抢注意力 | 取消通屏纹理与多余星形；中性表面分层；领地仅保留身份色线，状态由图形＋文字＋语义色表达 |
| 从导航进入管理或账本后，导航滚出视野 | 紧凑且保持可见的导航、锚点留白，保留现有三页路由 |
| 1440×900 首屏角色组织垂直间隔过大，390px 主题控件独占大行 | 收紧组织关系层间距；在窄屏保持文字与控件可读，不压缩为微型卡片 |
| 空地图只剩一行弱提示，错误原因挤在角落 | 统一静态 SVG 空状态插画；状态反馈回到内容流，读失败保持未知语义，不冒充成功 |
| 管理中心流程只画到指派；状态前出现重复字符图标 | 增加规划→指派→执行→呈报/审查→接受的静态流程；统一 SVG 图标，保留完整文字与权限原因 |

基线和预览保存在本地视觉验证记录中，未随发布分发。数据、名称、任务和执行均为合成测试，不代表真实运行。本节描述 2026-09-08 的历史三页布局；2.0 的六入口工作台见使用指南。

## 统一规范

方向：王国协作图谱。品牌使用“城门＋组织节点”的专用图形；角色保留 Owner 原作 SVG。以角色关系线作为辨识元素，避免添加与工作无关的装饰。

保留已存在的 parchment / night / forest / wine 主题与默认 forest；该选择来自当前产品，不来自历史宣传片。统一语义 token，不改变用户保存的主题偏好。

- 森林主题基础色：深松背景 `#13251F`、卡片松绿 `#1C342C`、抬升表面 `#254137`、主字 `#F0F4EA`、次字 `#B7C8BD`、品牌金 `#D8BE7C`。
- 状态：执行蓝、待审紫、接受/完成绿、异常红、未知琥珀、待命灰；各主题校准前景对比，不用颜色替代文字。领地身份色不表示权限或成功。
- 中文标题克制使用 `Noto Serif SC / Source Han Serif SC / STSong / serif`；正文 `Noto Sans SC / Microsoft YaHei UI / sans-serif`；技术编号 `Consolas / monospace`。不依赖远程字体下载。
- 间距以 4px 为步进，正文行高 1.55–1.65；圆角 8 / 12 / 16px；常用交互目标至少 40px，移动端重点控件 44px。
- SVG 统一 viewBox、currentColor、圆角线条；伴随文本的图标 aria-hidden、focusable=false；单独表达含义的图形有名称与文本说明。
- 动效仅保留原有角色表达与必要反馈；尊重减少动态效果设置。业务证据仍由原有投影与 Host gate 决定。

布局：

```text
品牌 / 三页导航 / 主题
当前读取状态
页面标题与一句说明
地图：宰相 → 领地 → 主管 → 执行者
管理：任务输入 → 操作抽屉 → 许可和 Owner 边界说明
账本：详情导航 / 证据类型 → 组织 / 任务 / 执行 / 史册
```

已复核：选择围绕组织关系与治理事实，保留产品主路径；不增设营销首页，不用纯装饰图形代替表单、事实或许可。

## 资源与实施批次

沿用 Owner 原作角色资源，来源与 AGPL-3.0-or-later 见 ASSETS_NOTICE.md。通用 SVG 优先取 Lucide 官方仓库必要子集，保留 ISC 及涉及 Feather 的 MIT 声明；无新增运行时框架或远程资源请求。来源：https://github.com/lucide-icons/lucide ，许可证：https://github.com/lucide-icons/lucide/blob/main/LICENSE 。对比度依据：https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html 。专用品牌/空状态/流程为本次原创几何 SVG。

1. 共享设计 token、样式与 SVG 模块；不改业务接口。
2. 接入地图、管理、账本：品牌/导航/角色标识、状态/空态、静态治理流程。
3. 当前源码编译与 GUI 回归；浏览器同状态复查、按真实发现修复；独立源码审查与主管验证分别记录。

## 覆盖与验收

| 页面/状态 | 必查项目 |
| --- | --- |
| 地图，有数据 | 1440×900、1024×768、390×844；真实几何连线，角色绑定不变 |
| 管理 | 创建输入、/ 选择领地、抽屉展开/收起、许可禁用原因；读取失败不开放动作 |
| 账本 | 入口→任务详情→返回；呈报/治理事实/运行观察/派生解释保留区别 |
| 全部四主题 | 文字、状态、焦点和边界清晰；选择状态明确且可保持 |
| 空白/加载/错误/会话过期 | 不虚构数据或成功，反馈可读，控件门禁保留 |
| 可访问性 | 键盘焦点可见；SVG 名称/装饰处理；缩放不裁切；减少动态效果 |

仅表示样式、静态图形与文案的改变不新建业务流合同。若实施中发现必须改变事件、状态、授权或失败处理，将在实施前单独评估并维护对应 Feature Flow。

验收区分源码实现、浏览器交互、静态检查与无法验证。构建成功不能替代视觉验收；合成 HTTP 测试不替代真实 DSH/Provider 验证。保护本轮前已有未跟踪文件，最终用哈希复核。禁止提交、推送或发布。
