# dsh-Kingdom 3.3.0 使用指南

日常只用三个入口：**运行总览、派发任务、主管设置**。也可以直接向 DSH 会话里的 AI 说需求，让它调用已开放的工具。

本指南对应 3.3.0。安装要求见 [README](../README.md#-快速开始)；正式下载入口为 [npm 3.3.0](https://www.npmjs.com/package/dsh-kingdom/v/3.3.0) 与 [GitHub v3.3.0](https://github.com/lusblead/dsh-Kingdom/releases/tag/v3.3.0)。通过官方 npm 下载并安装到 Web profile：

```bash
npm pack dsh-kingdom@3.3.0 --registry=https://registry.npmjs.org
dsh plugin --profile web add ./dsh-kingdom-3.3.0.tgz
```

安装或升级后重启原 DSH profile；使用其他 profile 时替换 `web`。已安装 3.2.1 的用户升级到 3.3.0 后可使用这三个入口，原版派发和恢复修复见 [3.2.1 说明](V3.2.1-RELEASE-NOTES.md)。

## 第一次使用

先在一个可用的 DSH 会话中说：

> 帮我查看 dsh-Kingdom 当前的王国、领地、角色和任务。我要把当前项目交给它管理；先说明缺少哪些配置，再逐项引导我确认。

已有王国和领地就继续使用。尚未初始化时，由人类在 DSH 的直接命令入口执行 `/kingdom init`。创建领地、登记执行者、模型配置和允许使用的能力，仍需经过现有的人类管理入口；让 AI 根据实际情况说明步骤和准备准确输入，不需要自己查内部编号。

准备一个负责统筹的会话和一个负责具体领地的主管会话。角色来自真实会话绑定，在网页里选择名称不会切换角色权限。宰相创建任务，主管指派、启动和审查任务；执行者的长期会话由执行流程建立，不需要提前手工创建。

在统筹会话中说：

> 把当前会话设为宰相，并引导我完成确认。

在希望担任主管的会话中说：

> 把当前会话设为「前端」的主管，并引导我完成确认。

将「前端」替换为工作台里真实、完整的领地名称。现有会话绑定引导覆盖宰相、主管任命与会话接替；其他首次配置仍使用原有管理流程，不能把这两句话理解成已完成全部初始化。

## 绑定或更换主管

在工作台的**主管设置**中查看各领地的主管和脱敏会话标识。点击“复制绑定主管请求”或“复制更换主管请求”，到你希望负责该领地的 DSH 会话发给 AI。

也可以直接说：

> 让当前会话负责「前端」。

> 把「前端」主管换成当前会话。

AI 会用当前真实会话与王国数据准备操作，并返回步骤和完整的人类管理窗口命令。你按以下顺序操作：

1. 将 AI 提供的完整命令直接放到**当前 DSH 会话的命令入口**执行一次，不修改其中字段。
2. 打开返回的管理链接。窗口预选本次目标；核对领地、角色与目标会话，点击“查看变更预览”。
3. 预览正确后点击“确认应用此变更”。这一步才写入绑定；只复制请求、生成命令或打开页面都不会更换主管。
4. 成功后让 AI 重新查看当前绑定，或回到主管设置重新读取，确认目标领地对应新的脱敏会话。

更换主管采用接替现有席位的方式，保留该席位与任务历史。如果同一席位负责多个领地，引导和管理窗口会列出全部受影响领地；确认后它们会一起由新会话负责。只想更换一个领地时，先停止确认，让会话说明如何调整主管安排。若领地名称不唯一、当前会话无法确认、绑定已变化，或存在未结算工作，按 AI 或窗口提示先核对；不要自行解除主管来绕过阻止。

这条路径让 AI 准备准确目标和输入。你只需说明负责哪个领地、核对预览并确认，不需要学习角色编号、会话编号或编辑 JSON。人类确认仍由你完成，AI 不能代替。

## 查看任务和会话

在对应 DSH 会话的直接命令入口执行 `/kingdom gui`，按宿主提供的链接打开工作台。默认进入**运行总览**。

| 列表 | 看什么 |
|---|---|
| 任务 | 任务名称、领地、执行者、任务状态、本次执行状态；点击任务名称查看详情 |
| 会话 | 当前登记角色、脱敏会话标识、领地、关联任务、已提供的执行观察 |

任务状态和执行状态分别显示。例如，任务仍在处理中，但本次执行已经结束，可能需要主管审查、返工或核对恢复结果。

| 任务状态 | 下一步 |
|---|---|
| 已创建 `CREATED` | 主管指定执行者 |
| 已分配 `ASSIGNED` | 主管核对本次权限后启动 |
| 处理中 `RUNNING` | 看本次执行记录；返工决定本身不会自动启动下一次执行 |
| 待审 `REVIEW` | 主管检查执行者结果，再接受、返工或判定失败 |
| 完成 `DONE` | 主管已接受；人类可继续查看交付，不等于人类最终验收 |
| 失败 `FAILED` | 查看失败原因，由主管说明后续安排 |

会话表只展示王国已登记角色与当前 Worker 长期会话，不是 DSH 的全部会话。**已登记、关联任务和执行记录，都不等于模型此刻正在生成。**主管职责范围内有运行任务时，若没有该会话的模型运行观测，仍显示未知。缺少观测不会当成闲置或已结束。

待处理、异常和最近交付在首页折叠区。地图、用量、账本等可从主管设置的高级记录进入。

## 派发一条任务

先在宰相会话中说清目标、领地和验收。例如：

> 在「前端」创建任务：修复登录页的窄屏布局。范围是登录页；验收是 390 像素宽度下没有横向滚动、按钮可以操作。先核对草稿，再创建。

宰相只能在已有领地创建任务，不能替主管启动。需要网页操作时，从宰相会话打开 `/kingdom gui`，进入**派发任务**，填写任务、范围、验收条件与领地，再点击“创建任务”。一句话输入只帮助填入草稿，不调用模型规划，也不会直接派发。

随后到该领地的主管会话说：

> 查看「修复登录页的窄屏布局」这项任务，为它指定可用执行者，核对本次所需能力后启动；结果回来后检查验收条件并给出审查结论。

也可从主管会话重新打开 `/kingdom gui`，在派发任务页完成“指定执行者”和“启动执行”。界面使用宿主允许的模式和能力；无法满足任务需要时，先让主管说明缺少什么。任命主管不会自动授予额外执行权限。

任务开始后，在运行总览查看进展。执行者提交结果会进入待审；主管接受后才变成完成。查看具体任务的详情，可以读取呈报和历史，并进入当前会话有权限的审查或恢复操作。

## 遇到提示时

| 提示或现象 | 怎么处理 |
|---|---|
| 创建任务或启动按钮不可用 | 让当前会话的 AI 说明原因；创建任务使用宰相会话，指派、启动和审查使用任务领地的主管会话，然后从该会话重新打开工作台 |
| 主管还没绑定，或想改由新会话负责 | 在主管设置复制请求，到目标会话交给 AI 引导确认 |
| 能力检查被拒绝 | 让主管核对任务要求、现有允许能力和运行配置；任命主管本身不会解决能力限制 |
| 工作区被占用 | 等前序任务结算后重新请求；系统不会自动把本项加入队列 |
| 恢复核对 `RECOVERING` | 让主管核对原执行；不要重复启动。跨重启的只读观察不自动生成执行回执或完成事实 |
| 提交结果不明或页面断开 | 先重新读取并核对事实，再决定下一步；不要反复点击写入按钮 |

当前流程需要会话按需读取、启动和审查，不承诺无人值守自动推进。发布与实际验证范围见 [3.3 版本说明](V3.3-RELEASE-NOTES.md)；功能回归通过不等于陌生用户能独立上手，真人上手验收仍未运行。
