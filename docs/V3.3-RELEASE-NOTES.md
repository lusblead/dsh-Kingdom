# dsh-Kingdom 3.3.0

3.3.0 将日常工作台集中为**运行总览、派发任务、主管设置**，并让 DSH 会话准备主管绑定或接替的完整确认步骤。普通用户先说要做什么，再核对准确目标；无需手查角色/会话编号或编辑 JSON。本版延续 3.2.1 的派发关联、可靠回执和只读恢复对账，不增加数据库迁移。

正式包入口：[GitHub v3.3.0](https://github.com/lusblead/dsh-Kingdom/releases/tag/v3.3.0) · [npm 3.3.0](https://www.npmjs.com/package/dsh-kingdom/v/3.3.0)。安装和完整操作步骤见 [当前使用指南](CURRENT-USER-GUIDE.md)。

## 本版变化

- **运行总览。** 首页分别显示任务和当前登记会话的领地、角色、关联任务与状态。任务状态、执行记录与模型此刻是否正在生成分别呈现；缺少会话运行观测时显示未知，不把关联任务当作模型正在运行。
- **集中派发。** 创建任务、指定执行者和启动执行集中在派发入口。宰相会话创建任务，所属领地的主管会话指派、启动和审查；按钮会说明当前权限或前置条件。网页选择角色名称不改变真实会话身份。
- **会话引导主管设置。** 设置页按领地展示主管，并可复制绑定或更换请求。到希望担任主管的 DSH 会话说“让当前会话负责「前端」”或“把「前端」主管换成当前会话”，AI 用真实上下文准备准确范围的十分钟管理窗口命令。
- **确认后再读回。** 会话准备不会写入绑定。人类复制完整命令、打开管理链接、核对预览并确认提交，随后重新读取绑定。窗口只预填准确目标；失效、歧义或关系变化不提供旧命令，未结算工作仍由现有守卫阻止。
- **明确整个席位的影响。** 更换主管会话沿用原席位及任务历史。同一席位如关联多个领地，摘要、步骤与窗口列出全部范围；确认后这些领地会一起由新会话负责。只想更换一个领地应停止确认，不能静默缩小席位变更的影响。
- **保留高级记录。** 地图、用量、账本、交付与既有详情操作继续可用，日常主导航只呈现三个入口。

## 验证与边界

已通过的开发检查包括 TypeScript 类型检查、构建、隔离回归以及本机 loopback Tool→Owner 窗口预览→显式确认→结果读回。主管引导测试覆盖首次绑定、原席位接替、多领地全范围、关系漂移、失效/外来/歧义拒绝与零写入边界；相关测试和流程契约随源码交付。

这些检查使用隔离数据库及明确的 Runtime/授权 fixture。本机 HTTP 和 DOM double 不代替真实 DSH/Provider 执行，也不证明真人能独立上手。

| 验证项目 | 当前结果 |
|---|---|
| 类型检查、构建与隔离回归 | 通过；发布记录核对最终测试结果 |
| 本机 Tool→Owner 窗口确认与读回 | 通过，Runtime/授权为 fixture |
| 当前版本真实浏览器交互 | 内置浏览器隔离 fixture：总览/详情/派发选择/主管请求复制通过；四主题与 390px 窄屏检查 |
| 陌生用户独立上手 | `NOT_RUN` |
| 完整真实 Provider 受治理执行 | `NOT_RUN` |
| 正式用户数据库迁移、生产性能 | `NOT_RUN` |

任务 `DONE` 仍表示主管接受，不等于人类最终验收或发布批准。会话身份、领地范围、能力检查和 Owner 人类确认没有被界面便利操作替代。

## 安装与升级

```bash
npm pack dsh-kingdom@3.3.0 --registry=https://registry.npmjs.org
dsh plugin --profile web add ./dsh-kingdom-3.3.0.tgz
```

安装后重启原 DSH profile。升级前核对未决执行，并一致备份 SQLite；WAL 模式不能只复制主数据库。DSH 与 Node 要求见 [README](../README.md#1-前置要求)。本版仅发布 DSH 插件，不包括本地 Codex 候选。

## 保留缺口

首次初始化、创建领地、登记执行者、模型与能力配置仍使用原有的人类管理流程；现有会话引导不能代替完整首次配置。当前也不提供安全作废未派发意图、冷启动权限/Fence 清理重建、子目录 WRITE 并发、自动排队或无人值守自动审查。找不到原派发输入仍是未知，不能据此重复启动。

3.2.1 的修复与两条 DSH 兼容线的历史验证范围保留在 [3.2.1 版本说明](V3.2.1-RELEASE-NOTES.md)，不能直接继承为本版完整模型执行或真人验收结果。
