# dsh-Kingdom v1.0.0 Release Notes

## 发布状态

本文件是 v1.0.0 的正式 Release Notes 文本。当前候选仍在本地隔离验证和独立审计中：尚未执行 commit、tag、push、GitHub Release 或 npm publish，因此不得据此推断 v1.0.0 已在任何远端发布。

## 主要内容

- 新增内置本地 GUI：王国地图、管理中心和王国账本提供任务、执行、审查与移交的有界投影；GUI 仅承载会话绑定的日常角色操作，不把浏览器、Cookie 或 HTTP 请求提升为 Owner Authority。
- `kingdom_start_task_governed` 是 canonical headless `GOVERNED_PERSISTENT` 入口。它要求可验证的 DSH caller session、领地 Supervisor scope、Capability Gate、Execution Lease、Dispatch evidence 与明确的恢复路径；Worker Claim 仍须经 Supervisor 审查，不能直接成为 `DONE`。
- 保留 `kingdom_start_task` 作为显式 `LEGACY_COMPAT` one-shot 入口。persistent 路径失败、证据不确定或处于恢复状态时不会自动降级。
- normal plugin `apply()` 不再创建或拥有 RunnerContext broker epoch。每次 governed dispatch 仍建立并 acquire 本地 canonical RunnerContext；只有调用方显式创建 public run-scoped Product lifecycle 时，才注册一个 epoch、ticket 与跨 realm bootstrap，保持单 epoch、anti-replay 与 fail-closed 边界。
- v1.0.0 采用 `AGPL-3.0-or-later`；v0.8.0 及更早版本维持其发布时的 `BSD-3-Clause` 许可。12 个 `src/gui/assets/characters/*.svg` 为 Owner 原创授权资产，作为 v1.0 候选包内容。

## 升级提示

- 使用 Node.js `>=22.19`，并在真实 DSH 环境中按 README 的 direct `/kingdom` Owner Control 路径配置 Owner、领地、角色/会话、Capability Ceiling 和 Worker execution profile。
- 已有 v3 数据库不会自动迁移；正式数据库迁移需要独立的 Formal DB Migration Gate。
- 使用 GUI 后执行 `/kingdom gui stop` 撤销本地 control session；不要重放 launch ticket、Cookie 或浏览器 payload。
